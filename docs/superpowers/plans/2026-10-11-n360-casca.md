# n.360 — fatia 1: casca e roteamento — Implementation Plan

> Spec: docs/superpowers/specs/2026-10-11-n360-casca-design.md


## Context

O dono decidiu (11/10/2026): o n.360 vira a plataforma-mãe e n.iso e n.privacy viram módulos dele. Tudo responde em
`n360.ness.com.br`, com os módulos em `/iso` e `/privacy`. A entrada mostra o início do n.360 com um cartão por módulo
(quem tem um módulo só entra direto nele). `niso` e `nprivacy` redirecionam. Um Worker, um banco. O n.360 antigo foi
desligado (o `n360.ness.com.br` responde 530). Spec: `docs/superpowers/specs/2026-10-11-n360-casca-design.md` (commit
`d27aa9d`, worktree `C:\Users\resper\worktrees\n360`, branch `feat/n360-casca`). Fatias 2 a 4 (conta e acessos,
permissão por pessoa, desativar e trilha) ficam fora daqui.

Hoje o produto vem do domínio (`frontend/src/produto.js`), nada usa o caminho da URL, e os arquivos estáticos
(`/login`, `/politicas`, `/auditor`, `/proposta`, `/assets/*`) respondem antes do Worker (sem `run_worker_first` no
`wrangler.jsonc:27-30`). O SPA já é entregue para qualquer caminho desconhecido (`src/index.ts:461-467`), então `/iso`
e `/privacy/x` já recebem o `login.html`.

## Decisões técnicas deste plano (complementam a spec)

1. **Redirecionamento em duas camadas, sem `run_worker_first`.** O Worker dá 308 nos caminhos que passam por ele; o
   `/login` e a raiz servidos como asset em `niso`/`nprivacy` carregam o SPA, que se redireciona (`location.replace`)
   no primeiro passo do boot. Evita rodar o Worker em todo asset e não mexe nos `_headers`.
2. **Caminhos que ficam no domínio antigo, sem redirecionar:** `/api/*`, `/scim/*`, `/mcp`, `/oauth/*`,
   `/.well-known/*`, `/health`, `/politicas*`, `/auditor*`, `/proposta*` (links de e-mail já enviados, IdP de SCIM,
   conectores MCP, chaves de API).
3. **SSO:** o `redirect_uri` enviado ao IdP continua o de `niso` (o IdP do cliente só cadastrou esse; o callback é
   exceção e responde lá). Os redirecionamentos finais do callback (`/#sso_token=` e `/#sso_erro=`) passam a absolutos
   em `${appUrl}`. Trocar o `redirect_uri` fica para quando os clientes cadastrarem o novo.
4. **MCP:** o recurso continua `https://niso.ness.com.br/mcp`; `hostsPermitidosMcp` passa a aceitar `niso` além do host
   do `appUrl`.
5. **Links de notificação** continuam `/projects/:id/:tela` (o parser de `handleNotificationClick` lê por posição); só
   `enderecoDoProduto`/`destinoDoAviso` mudam para caminho.

## Backend

- `src/config/url.ts`:
  - `APP_URL_PADRAO = 'https://n360.ness.com.br'`.
  - `HOST_DO_MODULO = { 'niso.ness.com.br': '/iso', 'nprivacy.ness.com.br': '/privacy' }`; `HOSTS_LEGADOS`
    (`n-iso`, `niso.ness.workers.dev`) passam a apontar para `/iso`.
  - `ORIGENS_EXTRAS = ['https://niso.ness.com.br', 'https://nprivacy.ness.com.br']` para o CORS; `NPRIVACY_URL` sai.
  - `fica(caminho)`: a lista de exceções (decisão 2), sem regex quadrática.
  - `URL_SSO_LEGADA = 'https://niso.ness.com.br'` para o callback (decisão 3).
- `src/index.ts`:
  - `fetch` (`:576-589`): host em `HOST_DO_MODULO` → `fica(caminho)` serve no lugar; senão 308 para
    `${appUrl}${prefixo}${caminho === '/' || caminho === '/login' ? '' : caminho}${search}`. `HOSTS_LEGADOS`: o mesmo,
    mas as exceções vão por 308 para o mesmo caminho no `appUrl` (comportamento atual, preserva método).
  - CORS (`:251-259`): aceita `appUrl`, `ORIGENS_EXTRAS` e loopback.
  - Comentário do catch-all registra que `/iso*` e `/privacy*` caem no shell (sem rota nova: nenhum asset tem esse nome).
- `src/mcp/servidor.ts:248-251` `hostsPermitidosMcp`: inclui `niso.ness.com.br`.
- `src/routes/public.ts`: `redirectUriDe` usa `URL_SSO_LEGADA`; `:316` e `:373` passam a `${appUrl(c.env)}/#sso_…`.
- E-mails com botão para a raiz (`src/routes/users.ts:133`, `src/services/avisos-prazo.ts:326,349`): texto "Entrar no
  n.360"/"Abrir o n.360"; o link continua a raiz (`appUrl`).
- `wrangler.jsonc`: `routes` + `{ "pattern": "n360.ness.com.br", "custom_domain": true }`; `vars.APP_URL` →

## Frontend

- `frontend/src/produto.js`:
  - Produtos `'n360' | 'iso' | 'privacy'`. `PRODUTOS` ganha `n360: { titulo: 'n.360 | ness.', inicio: 'inicio' }`;
    sai o `host`.
  - `produtoAtual(loc = location)`: `/iso…` → `iso`, `/privacy…` → `privacy`, o resto → `n360`. Saem o `?produto=` e o
    `sessionStorage['niso_produto']`.
  - `destinoLegado(loc)`: em `niso.`/`nprivacy.`/`n-iso.` devolve a URL do n.360 com o prefixo (`main.js` chama antes de
    tudo e faz `location.replace`). Em localhost e no `n360`, `null`.
  - `enderecoDoProduto(p)` → `'/'`, `'/iso'` ou `'/privacy'` (mesma origem). `destinoDoAviso` passa a devolver esse
    caminho.
  - `aplicarCasca('n360')`: título, marca "n.360" (sidebar, `.entry-mark`, `.login-brand-logo`), texto de entrada da
    plataforma, rodapés com "n.360", esconde `SO_ISO` e `SO_PRIVACY` (fica cadastro + Sistema). Nos módulos, como hoje.
  - `projetosDoProduto(lista, 'n360')` devolve todos os projetos.
  - `atualizarLinkCruzado`: num módulo mostra "n.360" (vai a `/`) e, quando o projeto tem os dois, "Abrir no
    n.privacy/n.iso" por caminho.
  - `semAcesso(c, 'n360')`: texto do n.360 (sem módulo em projeto nenhum).
- `frontend/src/views/inicio.js` (novo): `renderInicio(c, h, a)` — título "n.360"; projeto ativo (ou o primeiro);
  um cartão por módulo habilitado (`modulosDe`) com nome, uma linha e botão `data-action="abrirModulo"`
  (`location.href = enderecoDoProduto(m)`); abaixo `renderPontoDePartida(container, id, 'n360')`.
- `frontend/src/views/ponto-de-partida.js`: `produto === 'n360'` mostra os dois blocos (cobertura LGPD/ANPD e
  `iso_ajudados`).
- `frontend/src/globals.js` `initApp` (`:1389-1403`): produto `n360` → se todos os projetos visíveis têm um único
  módulo em comum, `location.replace(enderecoDoProduto(m))`; senão `navigate('inicio')`; sem projeto com módulo →
  `semAcesso`. `iso` sem projetos passa a cair em `semAcesso` também. Menu de conta (`:664`): versão por produto.
- `frontend/src/router.js`: ramo `S.view === 'inicio'` → `renderInicio`.
- `frontend/src/main.js`: `destinoLegado()` antes do resto; import de `inicio.js`.
- `frontend/src/views/project.js:473` `changeActiveProject` sem projeto: `navigate(PRODUTOS[produtoAtual()].inicio)`.
- `frontend/login.html`: item `#nav-inicio` ("Início", `data-action="navigate"` `["inicio"]`) no topo do menu, visível

## Revisão final (11/10/2026)

Decisões da revisão final, depois da execução acima (o texto anterior fica como estava):

- **Destino do redirecionamento vem do servidor.** `GET /health` devolve `app_url`; `destinoLegado` ficou async e, só em
  domínio antigo, lê o `/health` da mesma origem: se o `app_url` for outro host, `location.replace` para ele + prefixo; se for
  o próprio host ou o `/health` falhar, fica (sem laço). Saiu a constante `CANONICO` do `produto.js`. Volta atrás = `APP_URL`
  de volta para `niso`, e Worker e frontend deixam de redirecionar juntos.
- **Deploy em duas etapas.** O `wrangler.jsonc` volta ao `APP_URL` `niso` com a rota `n360` já declarada; a troca do
  `APP_URL` para o n360 é um PR de uma linha, depois de conferir `curl -s https://n360.ness.com.br/health` e de incluir o
  `n360` no widget do Turnstile. `APP_URL_PADRAO` no código continua n360 (os testes rodam nele).
- O Worker tira o prefixo do módulo já presente no caminho (`niso/iso/x` → `/iso/x`), e o item Início fica só na casca do n.360.
